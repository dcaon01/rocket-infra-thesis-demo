# State Backend Bootstrap

## 🎯 Purpose

This directory contains the bootstrap configuration to create the Terraform state backend infrastructure using CloudPosse's `terraform-aws-tfstate-backend` module (v1.7.1).

## 🏗️ What it Creates

- **S3 Bucket**: Encrypted storage for Terraform state files
- **DynamoDB Table**: State locking to prevent concurrent modifications
- **Backend Config Files**: Auto-generated `.tfbackend` files for each environment

## 🚀 Usage

### Quick Start

```bash
# Bootstrap backend state for dev environment
./scripts/bootstrap-state.sh dev backend keus

# Bootstrap frontend state for prod environment
./scripts/bootstrap-state.sh prod frontend client-prod
```

### Manual Bootstrap

```bash
cd bootstrap/

# Initialize (uses local state for bootstrap)
terraform init

# Plan
terraform plan \
  -var="environment=dev" \
  -var="component=backend" \
  -var="aws_profile=keus"

# Apply
terraform apply
```

## 📋 Requirements

- Terraform >= 1.6
- AWS CLI configured with appropriate profiles
- Appropriate AWS permissions for creating S3 and DynamoDB resources

## 🔧 Generated Files

After bootstrap, you'll find auto-generated files in `../backend-configs/`:

```
backend-configs/
├── dev-backend.tfbackend      # Generated by CloudPosse
├── dev-frontend.tfbackend     # Generated by CloudPosse
└── prod-backend.tfbackend     # Generated by CloudPosse
```

## 📁 Resource Naming Convention

CloudPosse module generates resources with this naming pattern:

```
S3 Bucket: {namespace}-{environment}-{project}-{component}-terraform-state
DynamoDB:  {namespace}-{environment}-{project}-{component}-terraform-state-lock

Example:
- keus-dev-rocket-backend-terraform-state
- keus-dev-rocket-backend-terraform-state-lock
```

## 🔐 Security Features

- ✅ **Server-side encryption** (AES256)
- ✅ **Versioning enabled** for state recovery
- ✅ **Public access blocked** completely
- ✅ **State locking** via DynamoDB
- ✅ **Force destroy** only in dev (data protection)

## ⚠️ Important Notes

1. **Run Once Per Account/Component**: Only run bootstrap once for each environment/component combination
2. **Local State**: Bootstrap itself uses local state (by design)
3. **Permissions**: Ensure your AWS profile has permissions to create S3 buckets and DynamoDB tables
4. **Cleanup**: If you need to destroy the bootstrap resources, use `terraform destroy` in this directory

## 🔄 Workflow

1. **Bootstrap** (this directory): Create state backend infrastructure
2. **Configure** (be/fe directories): Use generated `.tfbackend` files
3. **Deploy** (be/fe directories): Deploy your actual infrastructure

```bash
# 1. Bootstrap
./scripts/bootstrap-state.sh dev backend keus

# 2. Use in backend
cd be/
terraform workspace new dev
terraform init -backend-config=../backend-configs/dev-backend.tfbackend

# 3. Deploy
terraform plan && terraform apply
```

## 🆘 Troubleshooting

### S3 Bucket Already Exists
```
Error: Error creating S3 bucket: BucketAlreadyExists
```
**Solution**: The bucket name is already taken. Adjust the namespace or name variables.

### DynamoDB Permission Error
```
Error: AccessDeniedException: User is not authorized to perform: dynamodb:CreateTable
```
**Solution**: Ensure your AWS profile has DynamoDB permissions.

### Profile Not Found
```
Error: The config profile (client-prod) could not be found
```
**Solution**: Configure the AWS profile with `aws configure --profile client-prod`
